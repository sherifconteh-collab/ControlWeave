# Documentation review — PR #729

Performed live by a Claude Code session with direct PR/repo access (no
GitHub Action, no separate API key) — see `.claude/rules/doc-review.md`.

Cue: `docs-pipeline.yml` posted its "📚 Documentation Update Queued" comment on

## Fixed (real, verified discrepancies)

Both in `AUDIT_LOGGING.md`, which the queued comment did **not** flag — it
tracks `docs/guides/*` and this file sits at the repository root. It is also
the one document in the repo that describes this subsystem in detail, so it
was the only place the diff could actually invalidate prose.

- **`AUDIT_LOGGING.md` "Key behaviors"** claimed `logFromRequest`
  *"automatically extracts context (IP, user agent, session) from the request
  object."* Session was never extracted — the reads for it
  (`req.user.session_id`, `req.sessionID`) referenced fields that do not exist
  on this platform's stateless JWT auth, always evaluated to `undefined`, and
  were removed in PR #727. Corrected to name IP, user agent and request ID,
  and to state that `session_id` has no writer and `request_id` is the
  correlation field to use.

- **Same section** claimed audit-logging *"errors are swallowed/logged, not
  thrown."* As of PR #728 they are no longer swallowed: each failure is
  reported through the structured logger (`audit.write_failed`,
  `audit.siem_forward_failed`) so it reaches Sentry, and increments the
  `audit_pipeline` counter on the ops dashboard. Corrected, and the AU-5
  reasoning stated inline so the next reader knows why it is not "swallowed
  and forgotten" any more.

## Verified already correct — no change needed

- **All eight `docs/guides/*` pages the pipeline flagged.** Grepped every one
  for `ip_address`, `user_agent`, `actor_name`, `request_id`,
  `ai_decision_log`, "decision log" and "audit record fields" — **zero
  matches.** These guides describe user-facing behavior, and this PR changes
  only how audit records are written internally. No user-visible behavior
  changes, so nothing in them is invalidated. The pipeline flagged them
  because the diff touches route files those features live in, not because the
  prose is affected. The generator itself reached the same conclusion: its
  follow-up comment reported *"No documentation PR created — the generator
  produced no diff to commit."*

- **`AUDIT_LOGGING.md` field table** (lines 26-35) already lists `request_id`,
  `actor_name`, `ip_address`, `user_agent`, `outcome` and the rest correctly,
  and describes them as the AU-2/AU-3 field set. That table was accurate
  before this PR and is more accurate after it, because far more records now
  actually carry those fields. No edit needed — this is the case where the doc
  described the intended contract and the code has now caught up to it.

- **`AUDIT_LOGGING.md` `logFromRequest` signature example** (line 62) matches
  the call shape this PR standardizes on
  (`{ eventType, resourceType, resourceId, details, success }`). The 71
  converted sites conform to it.

## Noted but out of scope for this PR

- `AUDIT_LOGGING.md`'s "Where Logging Is Wired In" section enumerates specific
  routes (SSO, auth, and so on). It is not wrong, but it is now materially
  incomplete — 71 more handlers write through `auditService` than when it was
  written. Rewriting that section as an exhaustive list would make it a
  maintenance burden that goes stale on the next route added; it would be
  better re-framed as "all route handlers except the cross-tenant
  `platformAdmin` writes and the transactional sites". Left for a follow-up
  rather than half-updated here.
- The 30 raw inserts this PR deliberately does not convert (cross-tenant
  `platformAdmin` writes, transactional `client.query` sites, service-layer
  sites with no request context) are documented in the PR body with reasons.
  No doc in the repo currently claims otherwise, so nothing needed correcting.
