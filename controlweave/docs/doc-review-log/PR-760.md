# Documentation review — PR #760

A Claude Code session with direct repo access performed this review live. It covers the ERP audit readiness PR:
- financial audit readiness
- ERP access governance
- ERP transaction monitoring
- FIPS mode

Each guide was checked against the routes, services and migrations in the same branch.

This review was redone after the second and third rounds of commits. The second round moved ERP to a separately licensed **ERP Governance add-on** and added connectors, scheduled syncs, starter maps, manager routing, revocation tickets, three-way match and configuration monitoring (migrations 168 and 169).

## Added (new behavior, no prior doc)

- `docs/guides/FINANCIAL_AUDIT.md`: the four financial audit frameworks; the risk-control matrix and its CSV columns; test methods and the frequency table; statistical sample sizes (cross-checked against `samplingService` unit tests: 59 / 93 / 22 / 45 / 46 / 77); NFR/CAP flow; readiness rules. The rules are that gaps count only the five core assertions and exclude IT general and entity-level processes, and that the overall position is *qualified* whenever a material weakness is open.
- `docs/guides/ERP_ACCESS_GOVERNANCE.md`: import kinds and columns match `importService.KINDS`. Full-snapshot refusal on invalid rows, rule and function counts (47 and 39), role- and user-level analysis, resolve/reopen behavior, and revocation verification all match `sodService` and `reviewService`. The permissions match `routes/erpAccess.js`, including the named reviewer deciding with `erp.read`.
- `docs/guides/ERP_TRANSACTION_MONITORING.md`: the rule table matches `ccmService.RULES` (codes, severities, default settings), and the control-test conclusion wording matches `recordControlTest`.
- `docs/guides/FEDERAL_DEPLOYMENT.md`: the FIPS self-test description matches `config/fips.js`. Claims are limited to "uses a validated module", with bcrypt noted as outside the boundary.
