# Documentation review — PR #735

Performed live by a Claude Code session with direct PR/repo access — see
`.claude/rules/doc-review.md`.

Cue: `docs-pipeline.yml` posted its "📚 Documentation Update Queued" comment,
flagging `docs/guides/FRAMEWORKS.md`, `docs/guides/GETTING_STARTED.md` and
`docs/USER_GUIDE.md`. Unlike the previous PR in this series, this diff does
materially change what those pages describe: the 800-53 catalog goes from 300
controls to 1,014, and the FedRAMP baselines change from six hand-written
records to derived selections of 149/287/370.

## Fixed (real, verified discrepancies)

- **`docs/guides/FRAMEWORKS.md:14`** described NIST 800-53 as "20 families,
  300+ controls". Strictly still true after this PR, but "300+" understates
  1,014 badly enough to mislead someone sizing an engagement. Updated to state
  the real composition — 300 base plus 714 enhancements — and to mention
  baseline membership, which is the field that makes the enhancements usable
  rather than bulk.

- **`docs/guides/FRAMEWORKS.md:40`** listed "**FedRAMP** - Cloud services for
  government (coming soon)". This was **already wrong before this PR** —
  `fedramp_moderate` and `fedramp_high` have both been seeded frameworks for
  some time — and this PR makes it more wrong by adding a derived
  `fedramp_low` and taking the other two from six hand-written stubs to full
  baseline selections. Replaced with the three baselines and their control
  counts, and a note that they are derived from 800-53B so they cannot drift
  from the catalog they are defined against.

## Verified already correct — no change needed

- **`docs/guides/GETTING_STARTED.md`** — grepped for control counts and
  framework availability claims; it describes the onboarding flow rather than
  catalog contents, and nothing in it is invalidated by a larger catalog. No
  edits.

- **`docs/USER_GUIDE.md`** — its only 800-53 reference is a link to
  `frameworks/NIST_800_53.md`, which this PR updates directly. The link target
  is correct and the surrounding prose makes no numerical claim. No edits.

- **`docs/guides/FRAMEWORKS.md`** elsewhere — the crosswalk narrative ("If
  already have NIST 800-53, leverage crosswalks", the AC-2 worked example at
  line 150) remains accurate. AC-2 is still a base control, still crosswalked,
  and the enhancement import does not change what that example demonstrates.
  Worth stating explicitly because a reviewer might reasonably expect the
  crosswalk sections to need rework: they do not, because existing crosswalk
  lookups are exact composite matches on `(framework_id, control_id)`, so
  `AC-2` never matches `AC-2(1)` and no existing mapping becomes ambiguous.

- **`docs/frameworks/NIST_800_53.md`** was updated as part of the PR itself
  rather than as a review finding — it carried the most explicit stale claim
  in the repo ("Control enhancements (e.g. AC-2(1)) are not yet seeded"),
  which this PR falsifies directly.

## Noted but out of scope for this PR

- The **coverage gap on the enhancements is real and not closed here**: all 714
  arrive with no crosswalk mappings and no assessment procedures. That is the
  next PR in the series, and no doc currently claims otherwise, so nothing
  needed correcting — but a reader of `FRAMEWORKS.md`'s crosswalk sections
  should not infer that enhancements participate in crosswalks yet.
- `FRAMEWORKS.md:445`'s onboarding checklist item "Reviewed control counts"
  becomes considerably more work at 1,014 controls per framework activation.
  Not wrong, but the checklist assumes a catalog an operator can eyeball.
  Left alone rather than rewritten speculatively.
