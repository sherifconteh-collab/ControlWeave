# Documentation review — PR #744

A Claude Code session with direct repo access performed this review live. It covers the commits that added:

- durable storage
- the Policies screen
- 800-171/HIPAA content and the HIPAA risk assessment
- real connectors
- SAML/SCIM
- open-core licensing

Each guide was checked against the code in the same commit.

## Audit round (independent code review and TEVV-SEC)

This round fixed findings from an independent code review and added the TEVV-SEC CI layer.

- **`docs/guides/ENTERPRISE_SSO.md`**: "Require SSO" is no longer described as stopping password sign-in only. It now blocks password, passkey and social sign-in for non-administrators, and fails closed. This matches `services/ssoPolicy.js` and its callers (`routes/auth.js`, `routes/passkeys.js`, and the `/sso/exchange` step in `routes/sso.js`).
- **`docs/guides/INTEGRATIONS.md`**: the private-host rule now names the ITSM, Qualys and Splunk connectors and the Ollama URL. It also states that failures are reported as failed syncs, never as empty clean results. This matches the new `requestJson` use in `serviceNowService.js` and `qualysService.js`, `assertSafeUrl` in `splunkService.js`, and `assertTenantOllamaUrl`.
- **`docs/integrations/OLLAMA.md`**: explains when a local or private Ollama URL needs `CONNECTOR_ALLOW_PRIVATE_HOSTS=true`, and that the operator's `OLLAMA_BASE_URL` is not restricted.
- **`CI_CD_GUIDE.md`, `CLAUDE.md`, `.claude/rules/git-workflow.md` and `.claude/rules/code-review.md`**:
  - CI now has seven layers. The TEVV-SEC table matches `scripts/tevv-security-audit.js --list`.
  - TEVV-API-6, -7, -9 and -12 are recorded as moved to TEVV-SEC-1 to -4.
  - Reviews now run `npm run tevv:security`.
- **`backend/.env.example`**: documents `CONNECTOR_ALLOW_PRIVATE_HOSTS`.
- **Noted:** the performance metrics endpoints (`/api/v1/performance`) are now for platform owners. They were unreachable before, because no route authenticated the request. No guide documented them, so no doc change was needed.

## Audit round 2 (remaining findings fixed)

These fixes close the items the first audit round left open.

- **`docs/guides/ENTERPRISE_SSO.md`**
  - **Email domains** said an admin could register only their own email domain, and that the first organization to claim a domain held it. Both are gone. It now describes DNS TXT verification: the `_controlweave-verification.<domain>` record, the **Verify** step, one verified owner per domain, and that pending claims block nobody. Matches `routes/sso.js` (`saveEmailDomains`, `POST /sso/domains/verify`), `ssoService.findSsoByEmail` (verified domains only) and migration 163.
  - The IdP-initiated bullet now says each assertion is accepted once. Matches `samlService.consumeAssertion`.
  - The SCIM deactivate row says the last active administrator and platform administrators are refused. Matches `routes/scim.js` `assertMayDeactivate`.
- **`docs/guides/SECURITY.md`**: new section on where the browser keeps the session. The refresh token is in the HttpOnly `cw_refresh` cookie, requests carry the `X-CW-Client` header and must come from an allowed origin, tabs take turns refreshing, old stored tokens are upgraded once, and `REFRESH_COOKIE_SAMESITE` can tighten the cookie. Matches `utils/refreshCookie.js`, `frontend/src/lib/api.ts` and `tokenStore.ts`.
- **`docs/integrations/API_DOCS.md`**:
  - The login response example is still accurate for API clients.
  - Added: how refresh works in the body, the 30-second reuse rule, and that the web app gets the refresh token only as a cookie.
- **`docs/guides/INTEGRATIONS.md`**:
  - The connector paragraph says addresses are checked at connect time (DNS rebinding).
  - Webhooks gained the same rule, plus `WEBHOOK_ALLOW_PRIVATE_HOSTS` and `WEBHOOK_ALLOW_HTTP`. Delivery previously checked only the literal hostname and followed redirects. Matches `utils/netGuard.safeFetch` and `webhookService`.
- **`docs/COMMERCIAL_LICENSING.md`**: plans are read on every check, so changes apply at once on every instance. Only license verification is memoized, keyed by the key text. Matches `entitlementService`.
- **`CI_CD_GUIDE.md`, `CLAUDE.md`**:
  - SEC-5 now requires the pinned client.
  - SEC-10 added: refresh tokens go through `deliverRefreshToken`.
  - The table matches `tevv-security-audit.js --list`.
- **`backend/.env.example`**: documents `REFRESH_COOKIE_SAMESITE`, `WEBHOOK_ALLOW_PRIVATE_HOSTS` and `WEBHOOK_ALLOW_HTTP`.
- **`docs/integrations/SSO.md`** (flagged by the docs-pipeline comment after the round 2 push). Its setup steps described a UI that does not exist and have been rewritten to match `EnterpriseSsoPanel.tsx` and `samlService.spUrls`:
  - It listed fixed SP URLs (`/saml/metadata`, `/saml/callback`). The real URLs are per organization: `/api/v1/sso/saml/<org>/metadata` and `/acs`.
  - It described metadata XML upload, a **Test SSO Login** button and a `role` attribute mapping. The panel instead takes the sign-on URL, issuer, certificate and email attribute.
  - Added: domain verification, the IdP-initiated note, two troubleshooting rows, and a link to `ENTERPRISE_SSO.md`.
- **`docs/guides/ACCOUNT_SETUP.md`** §6.2 said SSO sign-ins may skip the TOTP challenge. `POST /sso/exchange` has enforced TOTP since Phase 0, so it now says SSO asks for the code and passkeys do not (`routes/passkeys.js` has no TOTP step). §6.4–6.5 (inactivity timeout, lockout, logout ending all sessions) remain accurate.
- **`docs/integrations/WEBHOOKS.md`**: the URL field now states the public-address rule and the two `WEBHOOK_ALLOW_*` settings.
- **Already accurate:** `SECURITY.md`'s session table (15-minute access, 7-day refresh, lockout, concurrent sessions). The lifetimes did not change.

## Fixed (verified discrepancies)

- **`docs/guides/INTEGRATIONS.md`**
  - It listed connectors as if all of them synced; only Okta, Entra ID, Jira, AWS Security Hub, Qualys and ITSM have sync clients. It now separates connectors that sync from those marked "sync coming soon".
  - It described a "Test" button that does not exist, and a Settings → Integrations path. It now describes the Integrations page and **Sync now**.
  - The SSO section gave the SAML ACS URL as `/api/v1/sso/callback/<provider>`, which is the social OAuth callback. The real per-organization ACS is `/api/v1/sso/saml/<org-id>/acs`. The section now points to `ENTERPRISE_SSO.md`.
- **`SAAS_STACK.md`**: storage (S3, R2) was marked "planned". It is implemented (`services/storageService.js`).
- **`docs/SMALL_START_DEPLOYMENT_PROFILE.md`**: the storage row now names the durable options (`S3_BUCKET` or a volume at `UPLOADS_DIR`).
- **`docs/guides/QA_SELF_TEST.md`**: the storage check now verifies durability, not just writability.
- **`docs/guides/FRAMEWORKS.md`**: 800-171 and HIPAA entries now state the real content (97 requirements; 40 implementation specifications, each Required or Addressable).
