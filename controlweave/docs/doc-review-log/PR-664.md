## The finding that framed this pass

Thirty-two images under `docs/screenshots/` were **200×40 placeholder stubs**,
not screenshots. The cause is on this PR's own comment thread: every
`docs-pipeline.yml` run reports

> Screenshots not captured (step outcome: `failure`) — likely missing
> DEMO_URL/DEMO_USERNAME/DEMO_PASSWORD secrets.

With no capture step working, the guides were written from the endpoints and
from intent. The backend of this product is well ahead of its frontend, and the
documentation had been describing the backend as though it had buttons.

That is the through-line for everything below: the docs were not sloppy, they
were written against the wrong artifact.

## Corrected — a behavioral claim that was subtly wrong

`POAM.md` said a control moving to compliant automatically creates a POA&M and
requires a `poam_justification`. That guard is real, but it lives on
`PUT /api/v1/controls/:id`. The control detail page calls
`/api/v1/implementations/:id/status`, which has no POA&M logic — so changing
status in the UI creates nothing and never asks for a justification. Now stated.

## A bug this review turned up

Screenshotting the Operations page failed because the page crashes.
`GET /poam` returns `{ data: { items, summary, pagination } }`; the page
assigned `res.data.data` straight to `poams` and called `.filter` on it —
`poams.filter is not a function`. The control detail page repeats the mistake
for POA&Ms and vulnerabilities, where it fails silently because `length` on that
object is `undefined`. Both fixed, here and in the `ai-grc-platform` mirror,
and verified live: Operations now lists the nine seeded POA&Ms with correct
counts.

## Out of scope — noted, not fixed

- **The frontend gaps themselves.** Making the docs honest is not the same as
  building the missing screens. That is real product work and belongs in its own
  PR.
- **`auditor-workspace/page.tsx`** uses `useState<any>` in two places, against
  `.claude/rules/coding-style.md`. Pre-existing and unrelated to this diff.
- **`routes/ai.js`** still calls `requireTier('enterprise')` on two
  reasoning-memory routes. Harmless — `requireTier` is a no-op — but contrary to
  `.claude/rules/tier-system.md`.
- **`docs-pipeline.yml`'s capture step** will keep failing until
  `DEMO_URL`/`DEMO_USERNAME`/`DEMO_PASSWORD` are set, so no screenshot in this
  repo can be refreshed automatically. Worse, the stubs got in through the
  `sync-stale-content` job: it runs `git add -A` and commits whatever is in the
  working tree, which is how `bb54355 docs(sync): auto-fix stale content` came
  to add 200×40 PNGs that `sync-doc-content.js` never writes. Both halves want
  fixing — set the secrets, and narrow that `git add` to the paths the sync
  script actually touches. Otherwise this recurs.
