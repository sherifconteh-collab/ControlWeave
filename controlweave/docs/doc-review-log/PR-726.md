# Documentation review — PR #726

Performed live by a Claude Code session with direct PR/repo access (no
GitHub Action, no separate API key) — see `.claude/rules/doc-review.md` for
why this replaced `claude-doc-review.yml`.

Scope: this repo has no automated feature-change detector posting a queued
comment, so the cue here was the review itself — an audit of the whole NIST
SP 800-53 AU control family prompted by the question "we track AU-2, but
what about AU-3 and the rest?". That audit found the FedRAMP deployment
guide asserting AU-2 through AU-12 compliance on mechanisms that do not
exist. Reviewed every AU-related claim across `docs/FEDRAMP_DEPLOYMENT_GUIDE.md`,
`ZERO_TRUST_ARCHITECTURE.md`, `README.md`, `AUDIT_LOGGING.md`,
`DYNAMIC_AUDIT_FIELDS.md`, `docs/DATABASE_ARCHITECTURE.md` and
`docs/wiki/security/README.md` against the actual implementation.

Note this PR is documentation-only. The underlying defects it stops
claiming away are fixed in follow-up PRs.

## Fixed (real, verified discrepancies)

- **`docs/FEDRAMP_DEPLOYMENT_GUIDE.md` §5** — the section opened "ControlWeaver's
  `audit_logs` table satisfies NIST AU-2 through AU-12 as follows" and then
  listed six rows that do not describe this codebase:
  - **AU-3** listed an `action` column. There is no such column; it is
    `event_type` (`001_initial_schema.sql:113`).
  - **AU-4** and **AU-11** both attributed storage management and retention
    to an `AUDIT_LOG_RETENTION_DAYS` cleanup job. `grep -rn "AUDIT_LOG_RETENTION"`
    returns **nothing** in either repo. No retention runs against
    `audit_logs` at all — `services/retentionScheduler.js:17-22` and
    `services/jobService.js:30-40` both filter `resource_type = 'evidence'`.
    AU-11 additionally instructed operators to "Set `AUDIT_LOG_RETENTION_DAYS=1095`
    (3 years) for High", which would have had no effect whatsoever.
  - **AU-8** claimed "All records use `timestamptz` (UTC)". `created_at` is
    `TIMESTAMP` **without** time zone (`001_initial_schema.sql:122`), which
    also contradicts `.claude/rules/database.md`'s own type table.
  - **AU-9** credited RLS with preventing modification. RLS provides tenant
    isolation, not write protection. The real append-only enforcement is the
    trigger pair in `121_audit_log_immutability.sql` — which the row did not
    mention at all, so the guide simultaneously under-credited the mechanism
    that works and credited one that does not.
  - **AU-12** claimed "All route handlers emit audit events via `auditLog.js`
    middleware". That middleware is imported by exactly one route file
    (`routes/dataSovereignty.js`, 6 routes) and returns early on any non-2xx
    status, so it cannot record failed operations.

  Rewritten as a status/implementation matrix. AU-4, AU-5 and AU-11 are now
  marked **Deployer-supplied** with an explicit instruction not to claim them
  on the strength of the table. AU-5 and AU-7 were previously absent from the
  table entirely despite the "AU-2 through AU-12" header and are now listed.
  AU-9 now credits migration 121 and states plainly that it is
  tamper-*resistant*, not tamper-*evident*. AU-10 now notes `user_id` is
  `ON DELETE SET NULL`.

- **`ZERO_TRUST_ARCHITECTURE.md:154`** — the Audit Logging row claimed
  "365-day retention" and pointed at `src/middleware/auditLogger.js`. Neither
  is real: no retention exists for audit logs (the 365 defaults in
  `jobService.js:46,298` are *evidence* retention), and there is no
  `auditLogger.js` in this repository — the middleware is `auditLog.js` and
  the primary writer is `services/auditService.js`. Both corrected.

- **`ZERO_TRUST_ARCHITECTURE.md:75`** — the field list named `action` (same
  non-existent column as above) and presented `session_id` as uniformly
  populated. Replaced with the real column names, plus a note that coverage
  is not uniform across writers and that `session_id` /
  `authentication_method` are populated for authentication events only.

## Verified already correct — no change needed

- **`docs/FEDRAMP_DEPLOYMENT_GUIDE.md` AU-6 row** — "Dashboard audit trail at
  `/dashboard/audit`" is accurate. The page exists at
  `frontend/src/app/dashboard/audit/page.tsx`, and the endpoints behind it
  (`GET /audit/logs` with user/event-type/resource/date filters,
  `GET /audit/stats`) work as described. Retained verbatim.

- **`README.md:67` "AU-2 compliant immutable audit logging"** — accurate **in
  this repository** and deliberately left unchanged. Migration 121's own
  header is candid that this README line was previously convention-only
  ("the only enforcement was that routes/audit.js never exposes an UPDATE or
  DELETE route. That's convention, not immutability"); the triggers that
  migration added make the claim real. This is the case worth calling out
  explicitly: the doc was ahead of the code, and the code caught up.
  The sibling `ai-grc-platform` repo has the same line with **no** equivalent
  migration, and it is corrected in the companion PR there.

- **`docs/wiki/security/README.md:40`** — "Complete audit trail with 15+ AU-2
  compliant fields" is fine; the table carries 20 columns after
  `048_audit_logs_au2_compliance.sql`.

- **`DYNAMIC_AUDIT_FIELDS.md:5`** and **`docs/DATABASE_ARCHITECTURE.md`** —
  spot-checked; neither makes a falsifiable AU claim. `DYNAMIC_AUDIT_FIELDS.md`
  refers generically to "standard AU-2 compliant fields" as the baseline that
  custom fields extend, which is fair. No edits.

## Noted but out of scope for this PR

- **`RELEASE_NOTES.md`** contains historical AU claims. Left untouched —
  release notes record what shipped at the time, not live behavior.
- The **underlying defects** are not fixed here, only the claims about them:
  the AU-8 timestamp type, the absent AU-4/AU-5/AU-11 mechanisms, and the
  uneven AU-3 field coverage caused by ~100 direct `INSERT INTO audit_logs`
  statements across 32 files that bypass `services/auditService.js`. Those
  land in follow-up PRs, at which point the AU-8, AU-5 and AU-11 rows in the
  guide should be revised again.
- `services/ce-mcp/audit-logger.js` claims compliance with "AU-2, AU-3, AU-12"
  in its header but writes to a console/file path only and never touches
  `audit_logs`. Pre-existing, unrelated to this diff, not modified.
