## The through-line

#664 concluded the docs "were written against the wrong artifact" — the
backend, not the product. Sharper form: **the backend was not merely ahead of
the frontend, it was disconnected from it.**

The compliance gate is the clearest case. `controls.js` demanded a
`poam_justification`, created the POA&M and filed a `poam_approval_requests`
row — complete, correct, and mounted on `PUT /controls/:id`, an endpoint the
dashboard never calls. Recording `other_than_satisfied`, NIST's canonical POA&M
trigger, produced nothing. `GET /poam/framework-types` served seven framework
vocabularies from behind a route-ordering bug that made it unreachable.
`'audit_finding'` and `'assessment'` were declared in `ALLOWED_SOURCE_TYPE` and
written by no code path. Each looked like a missing screen and was a missing
connection.

CMDB turned out to be the same story again: `asset_control_mappings` has been in
the schema since migration 005, commented *"Links assets to compliance controls
for traceability"* and indexed on both foreign keys, with no API and no UI. The
table was empty because nothing could write to it.

## Gaps closed as product work

Documentation was the wrong fix for most of what the first two passes found.

- **The gate now fires on the path the UI uses.** Extracted to
  `poamGateService` and enforced on `PUT /controls/:id`,
  `PATCH /implementations/:id/status` and `/test-result`.
- **Gaps raise draft POA&Ms** from failing tests, assessment procedures and
  findings, writing the two `source_type` values nothing had ever written.
- **CMDB asset↔control mapping, bulk import and register editing** are
  implemented. Editing is the one that mattered most day to day: with only Add
  and Delete, correcting a typo meant deleting the record and losing its id.
  The PUT endpoints and even the `update` client method already existed and had
  never been called.

## Pipeline — what running it found

#664's root cause is closed (`git add -A` narrowed to report-listed paths, the
capture step skips honestly without secrets). Actually dispatching it found four
more defects that no amount of reading would have:

1. Seeding skipped `seed:frameworks`, so `seed:demo:industries` hard-failed with
   its own instruction.
2. `require('playwright')` was unresolvable from the repo root. The pre-existing
   `npm install -g playwright` would not have helped either — npm's global
   prefix is not on node's require path. Never reached, because the step always
   died on the credentials check first.
3. Job-level `NODE_ENV=development` broke `next build`.
4. **`workflow_dispatch` published branch docs to the live wiki.** The push arm
   was guarded to `refs/heads/main`; the dispatch arm was not. This fired: an
   unmerged doc edit reached the public wiki as a side effect of testing an
   unrelated job. Both arms are now guarded.

Two capture-content defects, both caught by the integrity guard:

- The capture map produced byte-identical duplicates by construction, and seven
  affected names have committed screenshots the guides reference — so `--all`
  would have replaced correct images with the wrong page.
- Scroll and tab-click actions fail soft, silently producing duplicates whenever
  the page does not scroll or a selector misses.

Also: captures ran as `admin@technology.com`, the **lowest**-seeded demo org at
0.2 target compliance, so every dashboard rendered near-empty. Default is now
`admin@defense.com` at 0.9, whose CMMC/800-171/FedRAMP frameworks also exercise
the POA&M federal vocabulary.

### A guard that was tried and rejected

`check-screenshots.js` originally flagged images by bytes-per-pixel. It flagged
four files; **three were real screenshots** — a flat modern UI compresses about
as well as an empty page. Recorded in the script header as tried and removed
rather than quietly dropped: a guard wrong three times in four teaches people to
ignore it, which is the mechanism that let the original stubs survive.

## Still open

- **No Asset Coverage rollup.** The mapping data exists now; nothing aggregates
  it. Per control, `GET /cmdb/controls/:controlId/assets` returns the assets.
- **Three `useState<any>`** in `auditor-workspace/page.tsx`. Five fixed here,
  which surfaced an unguarded `agent.durationMs / 1000` rendering literal
  `NaNs`. The remaining three need the full engagement response shape declared
  (43 use sites) — its own change.
- **`routes/ai.js` `requireTier`** — still no-ops, still contrary to the rule.
- **`express-rate-limit` is undeclared in `backend/package.json`** despite being
  required by several route files. It resolves only because it is hoisted to the
  top level of `package-lock.json` (8.5.2). Fragile, pre-existing, repo-wide.
- **`openapi.yaml`** does not describe the new endpoints.
- **Demo secrets** remain unset; no tool here writes repository secrets. The
  capture job makes them optional rather than required.
- **Enterprise ITSM-grade CMDB** remains a much larger program than this PR:
  automated discovery and reconciliation, a configuration-item class model with
  inheritance, typed relationship semantics beyond the current dependency
  edges, change management, and service mapping. What is closed here is the gap
  between what the guide claimed and what the product did, plus the three
  functional holes that made the module hard to use for real work.
